版本 1.0 · 适用于 PlantFlow v1.0 / api.cloud.cenkor.cn

1 环境要求

服务器最低配置

环境CPU内存磁盘带宽
演示/轻量1 核2 GB20 GB5 Mbps
生产（建议）2 核4 GB50 GB SSD10 Mbps
高并发4 核+8 GB+100 GB SSD20 Mbps+

软件依赖

组件版本要求说明
Node.js≥ 22运行环境
PostgreSQL≥ 14（推荐 16）主数据库
Redis≥ 6队列、缓存、限流
Nginx≥ 1.20反向代理（生产环境）
Docker（可选）≥ 24容器化部署

可选依赖：pgvector 扩展（用于知识库向量检索，需 PostgreSQL 16 +）。

推荐：使用 docker-compose.fullstack.yml 全栈一键部署时，无需手动安装 PostgreSQL / Redis / pgvector，全部由容器内置（镜像 pgvector/pgvector:pg16），开箱即用。

2 宝塔部署

方案 A：纯反向代理（推荐）

后端 Express 已同时托管 API 和编译后的前端，最简方案是将域名全部反代到 127.0.0.1:5000。

步骤

  1. 宝塔面板 → 软件商店 → 安装 Node.js 版本管理器，安装 Node.js ≥ 22
  2. 安装 PostgreSQL（≥ 14）和 Redis（≥ 6）
  3. 创建数据库和用户
sudo -u postgres psql
CREATE USER api WITH PASSWORD 'your_strong_password';
CREATE DATABASE api OWNER api;
\q
  1. 上传项目代码到服务器（如 /www/wwwroot/api/）
  2. 配置环境变量
cp /www/wwwroot/api/.env.example /www/wwwroot/api/.env
# 编辑 .env：
# DATABASE_URL=postgresql://api:your_strong_password@127.0.0.1:5432/api
# REDIS_URL=redis://:密码@127.0.0.1:6379
# LLM_MASTER_KEY=$(openssl rand -hex 32)
  1. 安装依赖并构建
cd /www/wwwroot/api
npm install --omit=dev
npm run build
  1. 启动服务（使用 PM2 管理进程）
npm install -g pm2
pm2 start dist-api/server.js --name plantflow
pm2 save
pm2 startup
  1. 宝塔面板 → 网站 → 添加站点 → 域名设为你的域名（如 api.cloud.cenkor.cn）
  2. 设置 → 配置文件 → 替换为以下内容：
server {
    listen 80;
    server_name api.cloud.cenkor.cn;

    # SSL 配置由宝塔自动管理，保留 listen 443 ssl 等相关配置即可

    location / {
        proxy_pass http://127.0.0.1:5000;
        proxy_http_version 1.1;
        proxy_set_header Host              $host;
        proxy_set_header X-Real-IP         $remote_addr;
        proxy_set_header X-Forwarded-For   $proxy_add_x_forwarded_for;
        proxy_set_header X-Forwarded-Proto $scheme;
        proxy_read_timeout 120s;
        proxy_send_timeout 120s;
    }

    # WebSocket 支持（SSE 流式对话需要）
    location /api/v1/chat/ {
        proxy_pass http://127.0.0.1:5000;
        proxy_http_version 1.1;
        proxy_set_header Upgrade           $http_upgrade;
        proxy_set_header Connection        "upgrade";
        proxy_set_header Host              $host;
        proxy_read_timeout 86400s;
    }
}
  1. 在宝塔 SSL 面板申请并部署 SSL 证书
  2. 访问域名验证部署状态
curl -s https://你的域名/api/health

返回 {"ok":true 即部署成功。

方案 B：网站根目录 + API 反代

将 Nginx 直接托管前端静态文件，仅 API 请求反代到后端。

此方案需先将构建产物 dist/ 复制到网站根目录，并在 Nginx 中配置 SPA fallback（try_files $uri $uri/ /index.html）。

3 原生部署

不依赖宝塔面板，直接在 Linux 服务器上部署。

步骤

  1. 安装依赖
# Ubuntu/Debian
apt update && apt install -y curl gnupg
curl -fsSL https://deb.nodesource.com/setup_22.x | bash -
apt install -y nodejs postgresql postgresql-contrib redis-server nginx

# 确认版本
node -v   # 需 ≥ 22
psql --version  # 需 ≥ 14
redis-server -v # 需 ≥ 6
  1. 配置 PostgreSQL
sudo -u postgres psql
CREATE USER api WITH PASSWORD 'your_strong_password';
CREATE DATABASE api OWNER api;
\q
  1. 可选：安装 pgvector（向量检索）
apt install -y postgresql-16-pgvector
# 或从源码编译
# git clone https://github.com/pgvector/pgvector.git && cd pgvector && make && make install
# 然后在数据库中执行: CREATE EXTENSION vector;
  1. 配置 Redis
# 编辑 /etc/redis/redis.conf
# requirepass 你的redis密码
systemctl restart redis
systemctl enable redis
  1. 部署项目
mkdir -p /var/www/plantflow
# 上传项目文件到 /var/www/plantflow/
cd /var/www/plantflow
cp .env.example .env
# 编辑 .env 填入正确的数据库/Redis/LLM_MASTER_KEY

npm install --omit=dev
npm run build
  1. 使用 PM2 管理进程
npm install -g pm2
NODE_ENV=production pm2 start dist-api/server.js --name plantflow -i max
pm2 save
pm2 startup  # 按提示执行生成的命令
  1. 配置 Nginx 反向代理
cat > /etc/nginx/sites-available/plantflow << 'NGINX'
server {
    listen 80;
    server_name api.cloud.cenkor.cn;
    return 301 https://$host$request_uri;
}

server {
    listen 443 ssl http2;
    server_name api.cloud.cenkor.cn;

    ssl_certificate     /etc/nginx/ssl/你的证书.crt;
    ssl_certificate_key /etc/nginx/ssl/你的证书.key;

    location / {
        proxy_pass http://127.0.0.1:5000;
        proxy_http_version 1.1;
        proxy_set_header Host              $host;
        proxy_set_header X-Real-IP         $remote_addr;
        proxy_set_header X-Forwarded-For   $proxy_add_x_forwarded_for;
        proxy_set_header X-Forwarded-Proto $scheme;
        proxy_read_timeout 120s;
    }

    location /api/v1/chat/ {
        proxy_pass http://127.0.0.1:5000;
        proxy_http_version 1.1;
        proxy_set_header Upgrade           $http_upgrade;
        proxy_set_header Connection        "upgrade";
        proxy_read_timeout 86400s;
    }
}
NGINX

ln -sf /etc/nginx/sites-available/plantflow /etc/nginx/sites-enabled/
nginx -t && systemctl reload nginx
  1. 配置防火墙
ufw allow 22/tcp
ufw allow 80/tcp
ufw allow 443/tcp
ufw enable
  1. 验证
curl -s https://你的域名/api/health

systemd 方式（替代 PM2）

cat > /etc/systemd/system/plantflow.service << 'UNIT'
[Unit]
Description=PlantFlow Workflow Platform
After=network.target postgresql.service redis-server.service

[Service]
Type=simple
User=www-data
WorkingDirectory=/var/www/plantflow
Environment=NODE_ENV=production
ExecStart=/usr/bin/node dist-api/server.js
Restart=always
RestartSec=5
LimitNOFILE=65536

[Install]
WantedBy=multi-user.target
UNIT

systemctl daemon-reload
systemctl enable --now plantflow
systemctl status plantflow

4 Docker 部署

方式一：全栈一键部署（推荐，内置 PostgreSQL + Redis）

使用项目根 docker-compose.fullstack.yml，一条命令拉起「应用 + PostgreSQL（pgvector）+ Redis」，无需手动安装任何软件（镜像 plantflow-app:fullstack / pgvector/pgvector:pg16 / redis:7-alpine）。

# 1) 生成部署环境变量，并编辑 .env.fullstack 必填 POSTGRES_PASSWORD、LLM_MASTER_KEY
cp .env.fullstack.example .env.fullstack
#    LLM_MASTER_KEY 生成：openssl rand -hex 32

# 2) 一键构建并启动
docker compose -f docker-compose.fullstack.yml --env-file .env.fullstack up -d --build
  • 首次启动自动执行数据库迁移并创建演示数据（admin@example.com / admin123），无需额外初始化。
  • 若 POSTGRES_PASSWORD / LLM_MASTER_KEY 未填写，命令会直接报错提示，属正常保护行为，填入即可。
  • 容器、卷、网络使用固定 plantflow-fullstack / pflfs-* 命名，与其它应用完全隔离。
服务默认对外端口（.env.fullstack 可覆盖）镜像
应用FS_APP_PORT=5000plantflow-app:fullstack
PostgreSQL（含 pgvector）FS_POSTGRES_PORT=5544pgvector/pgvector:pg16
RedisFS_REDIS_PORT=6383redis:7-alpine

无外网 / 内网离线部署

bash docker/fullstack/export-fullstack.sh           # 联网机器上导出全部镜像为 tar.gz
docker load < plantflow-fullstack_*.tar.gz          # 目标机导入
docker compose -f docker-compose.fullstack.yml --env-file .env.fullstack up -d   # 无需再联网拉取/构建

常用运维命令

docker compose -f docker-compose.fullstack.yml --env-file .env.fullstack ps
docker compose -f docker-compose.fullstack.yml --env-file .env.fullstack logs -f app
docker compose -f docker-compose.fullstack.yml --env-file .env.fullstack down

方式二：传统方式（使用你已有的 PostgreSQL + Redis）

适用于已部署好数据库的场景，使用项目根 docker-compose.yml（host 网络模式），需要先在 .env 配置 DATABASE_URL（host 模式下主机用 127.0.0.1）、REDIS_URL、LLM_MASTER_KEY。

docker compose build
docker compose up -d
curl -s http://127.0.0.1:5000/api/health

部署维护（以 fullstack 为例）

操作命令
查看日志docker compose -f docker-compose.fullstack.yml --env-file .env.fullstack logs -f app
重启服务docker compose -f docker-compose.fullstack.yml --env-file .env.fullstack restart app
更新镜像docker compose -f docker-compose.fullstack.yml --env-file .env.fullstack up -d --build app
停止服务docker compose -f docker-compose.fullstack.yml --env-file .env.fullstack down
查看资源docker stats

5 配置说明

核心环境变量

变量必填默认值说明
DATABASE_URL是-PostgreSQL 连接串，格式：postgresql://user:password@host:port/db
REDIS_URL是-Redis 连接串，格式：redis://:password@host:port
LLM_MASTER_KEY是-32 字节十六进制密钥，用于加密 LLM API Key。生成：openssl rand -hex 32
PORT否5000服务监听端口
WORKER_CONCURRENCY否4工作流执行并发数（最大 32）
NODE_ENV否production运行模式

数据库配置建议

  • 生产环境使用强密码（至少 16 位，含大小写字母 + 数字 + 符号）
  • PostgreSQL 建议配置 max_connections = 200
  • 如需向量检索（知识库 RAG），安装 pgvector 扩展
  • 定期执行 VACUUM ANALYZE 保持查询性能

Redis 配置建议

  • 生产环境必须设置密码
  • 建议配置 maxmemory 1gb 和 maxmemory-policy allkeys-lru
  • 建议开启 lazyfree-lazy-eviction yes 避免大 key 阻塞

6 系统管理

管理员功能

左侧导航 → 系统管理，需要 tenant_admin 或 platform_admin 角色。

成员管理

角色权限说明
platform_admin平台超级管理员，可管理所有租户
tenant_admin租户管理员，管理本租户成员和工作流
developer开发者，可创建和编辑工作流
operator运营人员，查看执行和会话中心
agent客服人员，查看和回复会话

添加成员：点击「添加成员」→ 输入邮箱、密码、选择角色 → 确定。

审计日志

记录所有关键操作：工作流发布、成员变更、配置修改等。支持按时间和操作类型筛选。

多租户管理

platform_admin 可以在系统管理中查看所有租户列表，每个租户数据完全隔离。

重置用户密码

管理员可在成员列表中点击「重置密码」为成员重置。也可在服务器上使用命令行工具：

node reset_pw.mjs 用户邮箱 新密码

7 备份与恢复

数据库备份

# PostgreSQL 备份
pg_dump -U api -h localhost -d api > plantflow_$(date +%Y%m%d).sql
# 压缩备份
pg_dump -U api -h localhost -d api | gzip > plantflow_$(date +%Y%m%d).sql.gz

# 自动备份脚本（添加到 crontab）
# 0 3 * * * pg_dump -U api -h localhost -d api | gzip > /backups/plantflow_$(date +\%Y\%m\%d).sql.gz

数据库恢复

# 恢复
dropdb -U api -h localhost api
createdb -U api -h localhost api
psql -U api -h localhost -d api < plantflow_20260601.sql

# 从压缩文件恢复
gunzip -c plantflow_20260601.sql.gz | psql -U api -h localhost -d api

数据迁移

数据库迁移文件位于 api/migrations/，首次启动时自动执行。如需手动迁移：

# 重新执行所有迁移
psql -U api -h localhost -d api -f api/migrations/001_init.sql
# ... 按顺序执行每个 sql 文件

# 首次启动会自动执行迁移，删除所有表后重启也会重新创建
# 安全方式：NODE_ENV=development node dist-api/server.js  # 开发模式自动迁移

文件备份（部署配置）

# 备份 .env 和环境配置
cp .env /backups/env.backup.$(date +%Y%m%d)
# 备份整个项目（不包含 node_modules）
tar czf /backups/plantflow-source.$(date +%Y%m%d).tar.gz \
  --exclude=node_modules \
  --exclude=.git \
  /var/www/plantflow/

8 监控与日志

健康检查

# API 健康检查
curl -s https://你的域名/api/health
# 返回示例: {"ok":true,"db":"connected","redis":"connected","queueDepth":0,"uptime":12345}
配置外部监控（如 UptimeRobot）定期检查 /api/health 端点，异常时发送告警。

PM2 监控

pm2 list           # 查看进程列表
pm2 monit          # 实时资源监控
pm2 logs plantflow --lines 200  # 查看最近 200 行日志
pm2 show plantflow # 查看进程详情

Docker 监控

docker stats               # 容器资源使用
docker compose logs -f     # 实时日志
docker logs plantflow-api --tail 200  # 查看最近日志

应用层日志

PlantFlow 使用 console.log 输出日志。PM2 默认将日志输出到 ~/.pm2/logs/ 目录。

建议配置日志轮转：

pm2 install pm2-logrotate
pm2 set pm2-logrotate:max_size 100M
pm2 set pm2-logrotate:retain 7

执行队列监控

通过健康检查接口可以查看队列深度（queueDepth）。正常情况下队列深度应为 0 或很小的数值。如果持续堆积，说明执行速度跟不上入队速度，考虑增加 WORKER_CONCURRENCY。

9 升级指南

从源码升级

cd /var/www/plantflow

# 1. 备份
pg_dump -U api -h localhost -d api > upgrade_backup.sql

# 2. 拉取最新代码
git pull origin main

# 3. 安装依赖
npm install --omit=dev

# 4. 重新构建
npm run build

# 5. 重启服务
pm2 restart plantflow

从 Docker 升级

cd /www/wwwroot/api

# 1. 备份数据库（同上）

# 2. 重新构建镜像
docker compose build --no-cache api

# 3. 重启
docker compose up -d api

数据库迁移

服务启动时会自动检查并执行未完成的迁移（api/migrations/ 目录中的 SQL 文件）。迁移是幂等的，可安全重复执行。

升级后务必验证：curl -s https://你的域名/api/health 返回正常，并测试核心功能（登录、工作流执行）。

10 排错指南

服务启动失败

现象排查步骤
端口被占用lsof -i :5000 查看占用进程，修改 PORT 或停止占用进程
数据库连接失败检查 DATABASE_URL 是否正确；确认 PostgreSQL 正在运行：systemctl status postgresql
Redis 连接失败检查 REDIS_URL 是否正确；确认 Redis 正在运行：systemctl status redis
迁移执行失败查看服务日志中的具体错误，通常是权限问题或表中已存在数据

运行时问题

现象可能原因解决方案
AI 对话无响应模型配置错误或 API Key 失效在「AI · 模型」中测试连通性
知识库检索为空未配置 Embedding 模型切换为关键词检索，或配置 Embedding 后重向量化
定时任务未触发工作流未发布点击「发布」按钮
飞书/企微推送失败渠道配置错误检查 AppId/Secret，测试发送验证
工作流执行超时并发量过高或外部 API 慢增加 WORKER_CONCURRENCY，或优化工作流
登录失败密码错误或账号被锁定管理员重置密码：node reset_pw.mjs 邮箱 新密码
页面 404前端构建未更新重新执行 npm run build 构建前端

性能优化

场景优化措施
高并发工作流执行增加 WORKER_CONCURRENCY；使用更强的 CPU
大量知识库文档优化分段策略；使用 pgvector 索引；配置专用 Embedding 服务
页面加载慢配置 Nginx 缓存静态资源；启用 gzip 压缩；使用 CDN
数据库查询慢执行 VACUUM ANALYZE；检查慢查询日志；添加必要索引

安全建议

  • 生产环境必须使用 HTTPS
  • 定期更换 LLM_MASTER_KEY 和数据库密码
  • 使用强密码（推荐密码管理器生成）
  • 限制管理后台的访问 IP
  • 启用审计日志监控异常操作
  • 不要在代码或 .env 中提交真实密钥到 Git
