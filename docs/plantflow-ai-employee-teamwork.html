PlantFlow · AI 员工与团队协作可行性报告

现状实测结论先行落地路线与 v3 方案联动

本报告专门回答：「团队协作」与「AI 员工」这两件事，PlantFlow 现在能不能做？能做的边界在哪？以及要走到「真能用」最少要补什么？结论先给：两件事今天都不能做——本文会列出依据与最小可行路线。

核心结论（TL;DR）
  • 团队协作：工程机制近乎空白。无协作编辑、无评论/任务、无团队空间、无实时通知、无审计。是一等公民级缺失，要做是独立中型工程。
  • AI 员工：现有 Bot 是"关键词 + 表单 + 执行工作流"，本质是带表单的执行器，连 n8n Tools Agent / Dify Function Calling 的最低智能都达不到。要做真正的"AI 员工"必须先把方案 v3 的 N1-A（单 Agent 地基） 做出来。
  • 最少路径：AI 员工 = 先做 N1-A（必走），再做 N1-B（"员工感"必备）；团队协作 = 单独一条线，建议作为商业版差异化后置。

一、团队协作：现状

PlantFlow 当前在「团队协作」上的真实形态是单租户 + 多用户通过 tenant 共享数据，并没有把"团队"作为一等公民来设计。代码层面的检查项：

二、AI 员工：现状

"AI 员工"指的是：能理解意图、自主调用工具、有记忆、可持续工作的智能体。当前 Bot 是 "关键词 → 表单收集参数 → 执行预置工作流"，本质是执行器。

自主选择并调用工具无工具注册/调用机制不支持无 tool registry、Function Calling
多轮推理 / ReAct无不支持无思考链、无中间步

LLM 模型接入已有（豆包/通义/DeepSeek/智谱等国产）支持ai-models 页面支持多模型模板与测连
知识库 RAG 检索已有（pgvector + JSON 兜底）支持但无重排、无引用回显

换句话说，**今天 Bot"看起来智能"，本质是带表单的执行器**，不具备哪怕 n8n Tools Agent / Dify Function Calling 那种"能调用工具"的最低智能。

三、最少可行路线（要让两件事落地）

阶段 A · AI 员工地基（必走，没它后面都是"看起来像"）
  • A1 · N1-A 单 Agent（v3 已列）：LLM 意图识别（替换关键词） + 工具注册与调用（工作流/HTTP/知识库/连接器） + 会话记忆 + IM 自然语言触发
  • A2 · F1 队列可靠性 ＋ F2 超时/取消：Agent 多轮易卡，先有超时和重试才不会挂
  • 里程碑验收：在 IM 里问"今天有哪些质检异常"，Agent 自主解析 → 选工具 → 查库 → 返回结构化结果
阶段 B · AI 员工感与多角色（做到"像员工"的关键）
  • B1 · N1-B 多 Agent 编排：Orchestrator 主 Agent + 子 Agent 角色化（销售员/客服/质检员/财务助理等） + 任务分派 + 结果聚合 + 接力/并行
  • B2 · 主动巡检与异常推送：定时 Agent 主动看数 + 异常自动推送给对应负责人（与 N5 告警联动）
  • B3 · 知识库引用回显 ＋ 重排（O3）：让 Agent 答案可追溯
  • 里程碑验收："今天哪些异常 + 查库存 + 推送给负责人"，主 Agent 分派多个子 Agent 并行完成
阶段 C · 团队协作（独立中型工程，建议商业版差异化卖点）
  • C1 · 数据模型升级：新增 team / space / member / role；工作流 / Agent / 知识库挂到 team 下；保留 tenant 隔离
  • C2 · 协作编辑：实时协同（WebSocket / Y.js）+ 协作锁 + 评论与 @提醒 + 任务流转
  • C3 · 通知中心：站内通知 + 邮件 + IM 推送聚合
  • C4 · 审计日志 ＋ RBAC 细化（与 N8 联动）：所有写操作落审计、按资源授权
  • 里程碑验收：3 人团队同时编辑一个工作流，有评论、有提醒、有审计记录

五、风险与建议

  • 不要先把"团队协作"放第一位：协作是 UX/工程改造；不补 Agent 地基的话，协作编辑出来的还是"表单场景"，商业价值有限。
  • "AI 员工"是营销/产品名，工程上等同于"Agent + 工具 + 记忆 + 编排"。不要被名词带偏，逐项落到 v3 的 N1/F1/F2 即可。
  • 主动巡检（B2）是"员工感"的点睛之笔：哪怕其他都做了，没有主动巡检也只能"等问才动"，用户仍觉得是"查询工具"。
  • 团队协作（C）建议作为商业版差异化：开源独立版不强行做，工程资源优先堆在 Agent 与数据接入上。
  • 安全前提：A 阶段任何 prompt/参数/工具调用都必须租户隔离 + 限频 + 审计，避免一个 Agent 拿到另一租户数据。
本报告基于 PlantFlow 源码实测（2026-08-21）；核心依据来自 api/routes/bot-engine.ts、api/migrations/013_bot_assistant.sql、api/routes/admin.ts、src/pages/WorkflowEditor*。结论：两件事均未实现，须按 A→B→C 顺序落地。
