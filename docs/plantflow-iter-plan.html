🎯 北极星定位：自动运营大脑

PlantFlow 最终 = 把各系统（MES/CRM/考勤/第三方平台）数据自动汇聚到一处，做成全员可用的 IM 助理。服务对象：管理层（你 / 你姐）＋ 一线员工。目的就一句：把「整理数据、写总结、发通知、盯异常」这四件最耗时又最固定的活交给系统，人只看结果、只做例外决定。

四类核心活：① 自动报告总结（日报 / 周报 / 月报 / 年度总结）② 自动盯数＋异常预警 ③ IM 自动应答 ④ 自动跑流程（审批 / 报修 / 派单 / 通知）。

〇、差异化主线（先定方向，再做功能）

⭐ ① 多 Agent 协作（本次重点）
不是单机机器人，而是一个「团队」：主 Agent 理解意图并分派，多个子 Agent 各自干活（查库 / 生成 / 推送），并行协作，结果自动汇总回聊。直击当前最大短板。
② 对话即入口
所有能力先在钉钉/飞书/企微里能用：问一句就干活，而不是进后台拖节点。
③ 模板先于画布
分行业高频场景模板库（工厂/MES、餐饮、零售、医疗、教育、物流、通用办公……），按行业一键导入，别让用户对空白画布发怵。
④ AI 帮你搭
文字描述 → 自动生成工作流/Agent 配置，可微调。击穿 n8n/Dify 学习曲线。
⑤ 连接真实系统
优先补国产高频连接（数据库/表格/HTTP/邮件/云存储），没有连接器的自动化是半残。

工作量：S ≤ 0.5 迭代 ｜ M ≤ 1 迭代 ｜ L ≥ 2 迭代；优先级 P0 先做（差异化护城河）。

N1 落地细节（多 Agent 优先，建议内部再拆两子迭代）：
  • N1-A：单 Agent 地基 — LLM 意图识别（替换现有关键词匹配）、工具注册与调用（工作流/HTTP/知识库）、会话记忆。先把「能思考、能干活」的单 Agent 做出来。
  • N1-B：多 Agent 编排（联动本体） — Orchestrator 主 Agent ＋ 子 Agent 角色定义（例：查询 Agent/报表 Agent/推送 Agent）＋ 路由分派 ＋ Agent 间消息传递与结果聚合 ＋ 无依赖子任务并行。这是"多个使用联动"的落地。
  • 现有 `bot-scenarios` 体系平滑演进：保留表单式场景作为低门槛路径；新增 Agent 式场景走 N1-A/B。二者可在一个 IM 入口共存。

四、建议排期

阶段一（P0，打地基 + 「一个会协作的团队」）
  • N9 集中数据接入层 ＋ N4 第一批（自家数据库 / 自研接口）——先让数据流进来，这是自动运营大脑的前提
  • N1-A 单 Agent（思考＋调工具）→ N1-B 多 Agent 编排（本阶段重头；可能跨 3–4 迭代）
  • N2 分行业场景模板（工厂/MES 做深）＋ N3 AI 搭建
  • F1 队列可靠性 ＋ F2 超时/取消（Agent 多轮场景必须先有）
阶段二（P1，拓第三方 + 全员安全落地）
  • N4 第二批（第三方平台 API）＋ N5 告警
  • N8 RBAC / 数据可见隔离 ＋ F3/F4 限流/授权/多租户加固（全员开放的安全前提）
  • O1/O2：Bot 混合模式、编辑器调试与 Agent 调用链可视化
阶段三（P2，配套与运营）
  • N6 子工作流/版本 ＋ N7 运营计量 ＋ O3 知识库 ＋ O4/O5 联动
验收方式（体现多 Agent 联动，端到端）

在钉钉/企微里问：「今天有哪些质检异常？查一下 A 物料库存，并把日报生成后推送到产线群」。主 Agent 应能分派多个子 Agent 并行完成「查库 → 生成日报 → 推送群」，最后汇总回执给用户。能从一次会话由多个 Agent 协作完整跑通，即达标。

本方案基于 PlantFlow 源码实测（2026-08-21）；当前 Agent 为「关键词→表单→单场景向导」，无 LLM 语义、无工具调用、无多 Agent 编排。v3 把 PlantFlow 定位为「自动运营大脑」（数据汇聚 → 报告/预警/IM应答/流程，管理层＋一线员工都用），多 Agent 编排、数据连接器与集中接入层、细粒度权限为落地重点。工作量与优先级为建议值，可按团队节奏调整。
