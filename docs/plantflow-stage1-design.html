一、N9 集中数据接入层

1.1 数据模型（新迁移 019_data_sources.sql）

CREATE TABLE IF NOT EXISTS data_sources (
  id            UUID PRIMARY KEY DEFAULT gen_random_uuid(),
  tenant_id     UUID NOT NULL REFERENCES tenants(id) ON DELETE CASCADE,
  name          TEXT NOT NULL,                 -- 显示名，租户内可重名需唯一
  kind          TEXT NOT NULL,                 -- mysql|postgres|http
  config        JSONB NOT NULL DEFAULT '{}',   -- 非敏感字段（host/port/url/headers模板）
  credential_id UUID REFERENCES credentials(id), -- 敏感字段指向既有 credentials 表（加密）
  status        TEXT NOT NULL DEFAULT 'draft', -- draft|testing|active|error
  allow_query   BOOLEAN NOT NULL DEFAULT true, -- 查询/只读白名单开关
  field_allowlist JSONB NOT NULL DEFAULT '[]', -- 只允许暴露的字段（脱敏）
  last_ok_at    TIMESTAMPTZ,
  last_error    TEXT,
  created_at    TIMESTAMPTZ NOT NULL DEFAULT now(),
  updated_at    TIMESTAMPTZ NOT NULL DEFAULT now()
);
CREATE INDEX IF NOT EXISTS idx_data_sources_tenant ON data_sources(tenant_id);
设计要点：非敏感配置存 config，敏感凭证（密码/API key）指向 credentials 表（复用 AES-256-GCM）。这样不新造加密，且凭证可被 Connector/Agent 共享。

二、N4 第一批连接器执行器

2.1 MySQL / PostgreSQL 只读连接器（api/data-access/drivers/mysql.ts / pg.ts）

// pg.ts 示例（已有 pg 依赖）
import pg from 'pg'
import type { DataSourceDriver } from '../index.js'

export const postgresDriver: DataSourceDriver = {
  kind: 'postgres',
  async test({ source }) {
    const c = new pg.Client({ connectionString: buildConn(source), ...RO_ONLY })
    await c.connect(); await c.query('SELECT 1'); await c.end()
  },
  async query({ source, sqlOrReq, params }) {
    const c = new pg.Client({ connectionString: buildConn(source), ...RO_ONLY })
    await c.connect()
    const q = await c.query({ text: sqlOrReq, values: params, rowMode: 'array' })
    await c.end()
    return { columns: q.fields.map(f=>f.name), rows: q.rows, rowCount: q.rowCount ?? 0, durationMs: 0 }
  },
}
// MySQL: 需 npm i mysql2（新增依赖，仅运行时用）
  • 只读强制：连接串加 options=-c default_transaction_read_only=on（PG）/ connection.readOnly=true（mysql2）
  • 查询白名单：拒绝非 SELECT 开头（允许 WITH 开头纯 SELECT）；禁多语句（PG 用单语句协议，mysql2 multipleStatements:false）
  • 超时：statement_timeout 5000ms（PG）/ mysql2 queryTimeout 5000ms
  • 结果集上限：LIMIT 强制 / maxRows=1000 兜底

四、F1/F2 可靠性改造（改造增强沿用现有）

4.1 F1 队列重试/死信/幂等（engine/queue.ts + store + 新迁移 021_queue_reliability.sql）

-- 在现有 execution_jobs 上扩展（若字段已存在则跳过，幂等）
ALTER TABLE execution_jobs ADD COLUMN IF NOT EXISTS attempt_count    INT  NOT NULL DEFAULT 0;
ALTER TABLE execution_jobs ADD COLUMN IF NOT EXISTS max_attempts     INT  NOT NULL DEFAULT 3;
ALTER TABLE execution_jobs ADD COLUMN IF NOT EXISTS next_attempt_at  TIMESTAMPTZ;
ALTER TABLE execution_jobs ADD COLUMN IF NOT EXISTS last_error       TEXT;
ALTER TABLE execution_jobs ADD COLUMN IF NOT EXISTS dedup_key        TEXT;  -- 幂等键
ALTER TABLE execution_jobs ADD COLUMN IF NOT EXISTS dead_letter_reason TEXT;
CREATE INDEX IF NOT EXISTS idx_jobs_retry ON execution_jobs(attempt_count, next_attempt_at);

CREATE TABLE IF NOT EXISTS dead_letters (
  id        UUID PRIMARY KEY DEFAULT gen_random_uuid(),
  job_id    UUID,
  tenant_id UUID,
  reason    TEXT,
  payload   JSONB NOT NULL DEFAULT '{}',
  created_at TIMESTAMPTZ NOT NULL DEFAULT now()
);
  • 重试：claimExecutionJob 改为只捞 attempt_count < max_attempts AND (next_attempt_at IS NULL OR next_attempt_at <= now())；失败触发指数退避 1s/4s/16s；达上限转死信。
  • 死信：写 dead_letters + 可重投（回到 pending）。
  • 幂等键：入队时 dedup_key = hash(tenant+triggerType+workflowId+外部事件 id)；唯一约束=同一 dedup_key 同一时间窗(如 24h)不再 enqueue。

4.2 F2 超时/取消/循环上限（engine/executor.ts + engine/agent/runner.ts）

  • 整体超时：runWorkflow 外层 AbortController + EXEC_TIMEOUT_MS(默认 60s)；超时置 cancelled 并记录。
  • 节点级超时：executor 对单个 node 包 Promise.race(timeout)（默认 10s，可用环境变量 NODE_TIMEOUT_MS）。
  • 循环上限：logic.loop/logic.parallel 现有实现加 MAX_LOOP_ITEMS(默认 500) 与 MAX_DEPTH(默认 20) 保护，超过直接 failed。
  • Agent 内超时：runAgent 全程受 timeout_ms 约束；max_turns 兜底防死循环。
  • 取消传播：前端取消执行 → 更新状态 cancelled → 运行中的 AbortController abort。
验收：故意构造一个慢查询/死循环工作流，能按预设超时被中止并标记 cancelled；队列里积压的任务按退避重试，超过阈值进死信；同一事件不重复入队。
